## 时间与运行模式

- 时区：Asia/Shanghai。
- 自动化心跳：Codex重复规则使用工作日每5分钟，不编码小时；心跳收到后转换到 `Asia/Shanghai`，仅在北京时间09:30—11:30和13:00—15:20（首尾均含）进入业务路由，其余时间静默。这样避免调度器把规则小时按UTC解释而整体错后8小时。心跳用于及时路由业务档位及重试 `pending` / `pending_send`，不把5分钟心跳本身解释为5分钟报告档。
- 自动化提供的 `current_time_iso` 是带时区的绝对时间。若值以 `Z` 结尾，先按UTC解析，再转换为Asia/Shanghai后匹配档位；禁止直接使用原字符串的小时和分钟。例：`2026-08-13T05:10:41Z` = `2026-08-13 13:10:41+08:00`，应归属已经到达的13:10档。
- 标准盘中报告：A股交易日09:30—11:30、13:00—15:00的每个标准10分钟档。
- 固定趋势样本：10:00、10:30、11:00、11:15、13:30、13:45、14:00、14:30、14:45。
- 仅取样不推送：11:15、13:45、14:45。
- 收盘报告：15:10，使用Wind实时落库的15:00收盘值。
- 不设置执行宽限、超时放弃或“超过N秒不补跑”。档位一旦被任务触发，就必须持续执行或进入待重试队列，直至完成。
- 每次触发先重试当日 `pending` 档位，再处理本次触发对应的最新已到达档位；`pending` 按计划时间从早到晚处理。不得自动补发从未触发且未登记为 `pending` 的历史档位。
- 计划档位、实际执行时间和Wind交易时间分别记录。延迟取得的实时数据必须展示真实数据时间，不得伪装成计划时点数据。
- 同一“交易日 + 计划档位 + 模式”只成功执行一次；已完成重复触发静默。任一步失败都记录失败阶段并保留 `pending`，后续触发从可恢复阶段继续。
- 休市、交易日不符或有明确时间证据表明核心数据陈旧：静默结束。不同档位返回相同数值不等于陈旧。
- 13:00使用11:30最后成功采样作为上一周期并标注“跨午休比较”。

## 双渠道输出

所有渠道必须来自同一份完整计算结果。精简只发生在展示层，不得减少Wind查询、计算字段、状态字段或审计文件。

### 飞书

- 只发送精简版互动卡片，一次报告档原则上只发一张卡；超出单卡限制时才按自然章节拆卡。
- 使用卡片 JSON 1.0 兼容结构和 `wide_screen_mode: true`。主体优先使用 `div.fields`、`hr`、`table`、`note` 和短 Markdown，不把全部内容塞入一个 Markdown 文本块。
- 卡片标题使用 `HH:mm 主力资金｜核心状态`；核心状态从四指数合计方向和最近一周期变化确定，不编造投资结论。
- 中国市场配色：净流入或加仓为红色，净流出或减仓为绿色，缺失或样本不足为橙色，其它为蓝色。颜色只用于标题和关键状态，正文避免过度装饰。
- 第一屏依次突出四指数主力合计、最近一周期变化、较当日基准变化。数据时间放在末尾弱化显示。
- 只在发生缺失、少返、陈旧或跨午休时显示“数据提示”；正常固定说明压缩为一行尾注。
- 不附完整审计表，不另发第二条完整报告。

### 飞书精简卡片视觉规范

按以下顺序构建卡片；盘中卡片使用四个表格组件，收盘卡片使用一个表格组件，不超过飞书单卡五个表格组件的限制。

1. **标题栏**：标题前加 `📊`；净流入或加仓主导时 `template: red`，净流出或减仓主导时 `template: green`，缺失或样本不足时 `template: orange`，其它情况 `template: blue`。
2. **核心指标区**：使用一个 `div.fields` 放置三项双列字段，字段标题分别加 `💰 当前合计`、`⏱ 近10分钟`、`🏁 较日内基准`。金额用粗体，正负值按下方“涨跌视觉映射”显示。
3. **摘要区**：使用单独 `div`，以 `🔎` 开头，只保留一句客观摘要。
4. **分隔**：核心指标、市场、自选股、行业、尾注之间使用 `hr`，不要依赖空行模拟分区。
5. **市场表**：标题 `📈 代表指数`；列为“指数、当前主力、近10分钟、状态”，四个指数各一行。状态列使用 `options` 类型彩色标签。
6. **自选股表**：标题 `⭐ 自选股`；列为“股票、涨跌、主力、近10分钟、状态”，3只股票按监控清单顺序各一行。涨跌和金额列使用 `lark_md`，状态列使用 `options`。
7. **行业表**：分别使用 `🔥 行业净流入 Top 5` 和 `🧊 行业净流出 Top 5` 两个表格；列为“#、末级行业、净额、Top 3 个股”。列宽固定为 `7% / 24% / 20% / 49%`，首列居中，内容顶部对齐，行高为 `88px`。Top 3 单元格使用 `lark_md`，每只股票用 `简称 资金/涨跌幅`，三只股票各占一行，禁止使用单行分隔符导致内容被省略。
8. **尾注**：只用 `note` 弱化展示数据时间；不显示固定来源或主力口径文案。仅在实际少返、缺失、陈旧或跨午休影响结果时，额外增加以 `⚠️ 数据提示` 开头的橙色提示块。

收盘卡片使用同一个 `scripts/render_feishu_card.py`，由规范化输入中的 `top10` 字段自动识别收盘结构。卡片包含三项核心指标、一句客观摘要和一张Top 10表格；表格列宽固定为 `8% / 22% / 23% / 17% / 30%`，列为“#、股票、主力净流入、涨跌、全日趋势”，趋势使用彩色状态标签。收盘档不得调用盘中四表结构，也不得因结构不匹配而手写替代卡片。

#### 涨跌视觉映射

- 正数：`<font color='red'>↑ +数值</font>`。
- 负数：`<font color='green'>↓ -数值</font>`。
- 零值：`<font color='grey'>→ 0.0</font>`。
- 缺失：`<font color='orange'>⚠ Wind未返回</font>`。
- 不要用 emoji 颜色替代实际数值；箭头、正负号和数值必须同时保留。

#### 状态标签映射

- `持续流入`、`持续加仓`：red。
- `流出收窄`、`波动加仓`：orange。
- `流入转流出`、`流出扩大`、`持续减仓`、`波动减仓`：green。
- `基本持平`、`基本稳定`：neutral。
- `基准建立中`、`样本不足`、`Wind未返回`：orange。

如果表格组件构建或发送失败，不得直接把整份报告降级成一个长文本块并标记成功；保留已落盘结果和待发送卡片，标记 `pending_send`，并在后续触发优先重试，直到发送成功。

### Codex

- 先输出与飞书信息等价的精简Markdown版，使用相同的章节图标、`↑/↓/→` 涨跌标识和紧凑表格；Codex不输出飞书专用 `<font>` 或 `text_tag` 标签。
- 随后以二级标题 `完整报告（审计）` 输出全部规定字段和必要限制。
- 精简版与完整审计版的数值、排名、状态和数据时间必须一致；若不一致，以完整计算结果为准并修正精简版。

## 盘中精简版

按以下顺序展示：

1. 标题：`HH:mm 主力资金｜核心状态`。
2. 核心指标：四指数当前主力合计、最近一周期变化额、较当日基准变化额。首次采样显示“基准建立中”；不在精简版显示两类变化率。
3. 一句客观摘要：指出合计方向、最近周期是增强还是收窄、资金最强和最弱的代表指数；只能基于已返回数据，不给买卖建议。
4. 四板块：每个代表指数只显示当前主力净流入、最近一周期变化额、资金状态。不显示主力占比、变化率和较基准明细。
5. 3只自选股：按监控清单顺序逐只显示涨跌幅、主力净流入、最近一周期主力变化额、资金状态。机构/大户/中户/散户继续查询并保存在完整审计版；只有明显缺失或口径异常时在精简版追加弱提示。
6. 行业异动：完整保留净流入Top 5和净流出Top 5；每个行业完整保留主力资金流入Top 3个股，但使用紧凑格式。
7. 数据时间和必要提示。

### 行业异动紧凑格式

每个行业占一个紧凑信息块：

`1. 末级行业名  ↑ +18.2亿`

`中际旭创 ↑+4.2亿/↑+2.8%｜新易盛 ↑+3.6亿/↑+2.1%｜天孚通信 ↑+1.9亿/↑+1.4%`

规则：

- 精简版行业只显示排名、末级行业名和主力净流入额；不显示完整路径、主力流入额、主力流出额或行业分户汇总。
- 末级行业名取 Wind 原始行业路径按精确分隔符 `--` 切分后的最后一个非空片段；没有 `--` 时使用原值。不得按单个连字符拆分。原始完整路径必须原样保存在状态文件和完整审计版。
- 每只个股只显示简称、主力净流入额和涨跌幅，格式为 `简称 ±资金亿元/±涨跌幅%`。
- 不显示股票代码，只有简称重名或无法明确识别时才追加Wind代码。
- 个股仍严格按主力净流入额排名；涨跌幅不参与排名。
- 缺失字段在对应位置写“Wind未返回”，不得省略整只个股或用0替代。

## 盘中完整审计版

### 顺序

1. 标题、生成时间、Wind数据时间。
2. 四指数主力资金合计高亮。
3. 市场板块概览。
4. 自选股明细。
5. 行业净流入Top 5。
6. 行业净流出Top 5。
7. 必要的数据限制。

### 四指数合计高亮

展示：当前主力合计及净流入/净流出方向、最近一周期变化额、最近一周期总变化率、较基准变化额、较基准变化率。

四指数任一当前值缺失，不用其余三项冒充完整合计，显示“Wind未完整返回”。

### 市场板块表

列：板块、代表指数、当前主力净流入、主力占比、最近一周期变化额、最近一周期变化率、较基准变化额、较基准变化率、资金状态。

### 自选股表

列：股票、当前涨跌幅、主力净流入、主力占比、机构、大户、中户、散户、最近一周期主力变化额、最近一周期变化率、较基准变化额、较基准变化率、资金状态。

### 行业表

分别输出净流入Top 5和净流出Top 5。列：排名、Wind行业完整名称、主力流入额、主力流出额、主力净流入额、行业资金流入Top 3个股。

行业个股格式：`股票简称（主力净流入额亿元，当前涨跌幅%）`。个股按主力净流入额排序，涨跌幅不参与排名。Wind不返回完整行业成分或排名时写“Wind未返回”，不得用行业外股票或不完整样本补齐。

行业机构、大户、中户、散户汇总仅在Wind可靠直接返回时追加；否则注明“Wind行业接口未提供”。

## 趋势采样

每个固定时点对四个上市板块各取主力净流入Top 5。候选可随时间变化；保存所有实际返回候选，以便最终入榜股票回溯可用样本。

固定时点不得改成其它计划时点。任务即使延迟执行，仍归属已触发的原计划样本，并保存真实执行时间和Wind时间；失败样本进入 `pending`，后续触发继续尝试。延迟时只能取得当前实时数据时必须如实记录Wind时间，不得伪装为计划时点快照。最终股票少于3个有效点时显示“样本不足”。

固定样本文件按“计划时点 + Wind代码”去重。若该计划档位已经成功保存，不因重复心跳再次查询或覆盖。

## 收盘精简版

按以下顺序展示：

1. 标题：`15:10 收盘主力榜｜核心趋势`。
2. 核心指标：Top 10主力净流入合计、有效股票平均涨跌幅、最值得关注的资金趋势状态；不计算或展示上涨/下跌家数。
3. 明确榜名为“四板块各Top 5候选合并榜”，不得简称为全A Top 10。
4. 第1—5名逐行显示：排名、股票简称、主力净流入额、涨跌幅、全日资金趋势。
5. 第6—10名使用紧凑行显示相同五项，不删除任何入榜股票。
6. 只有数据少返、样本不足或时间异常时显示数据提示；末尾只保留数据时间。

默认不在精简版显示Wind代码、来源板块、板块内排名、所属行业、主力占比、趋势变化额和有效样本数；这些字段必须保留在完整审计版。简称重名时追加Wind代码。

## 收盘完整审计版

### 候选和排名

1. 四板块各自取5只不同股票，共最多20条。
2. 按Wind代码去重，记录全部来源板块；正常情况下上市板块互斥。
3. 按15:00当日主力净流入额降序取综合Top 10。
4. 榜名必须包含“四板块各Top 5候选合并榜”，不得声称完整全A Top 10。
5. 任一板块少返时写明实际返回数量，不用其它来源补齐。

### 高亮

- Top 10主力净流入合计。
- Top 10平均收益率：有效涨跌幅的算术平均，不按市值或资金金额加权；不足10只注明样本数。
- 不展示上涨、下跌家数。

### 表格

列：综合排名、股票、Wind代码、来源板块、板块内排名、所属Wind行业、当日涨跌幅、主力净流入额、主力净流入占比、全日资金趋势、趋势变化额、有效样本数。

15:00收盘值不加入趋势样本；趋势变化额等于最后有效固定样本减首个有效固定样本。

## 计算规则

### 计划档位解析与去重

1. 将自动化传入的带时区当前时间解析为绝对时刻，再用IANA时区 `Asia/Shanghai` 转换；不得把 `Z` 时间当作本地时间，也不得丢弃UTC偏移。
2. 读取当日状态，先选择计划时间最早的 `pending` 档位重试；不存在 `pending` 时，选择不晚于当前北京时间的最新计划档位。不得提前执行未来档位。
3. 同一触发过程中完成一个 `pending` 后继续处理其余 `pending`，最后处理本次最新已到达档位；不得因为已超过计划时刻或运行跨入下一档而中止。
4. 执行前检查完成状态；已成功完成相同模式的档位静默跳过。只对实际触发过或已登记 `pending` 的档位执行，不扫描补发未触发的历史空档。
5. 首次开始处理时记录 `triggered_at` 和计划档位；任一步失败记录 `pending`、`failure_stage`、`last_error`、`last_attempt_at`，后续触发从已有落盘结果继续，避免重复取数。
6. 报告档完成Wind校验、计算、全部状态落盘和飞书发送后才记录 `completed`、实际完成时间和Wind数据时间；纯取样档完成规定状态落盘后才记录完成。

### 数据时效校验

1. 时效证据按优先级使用：Wind返回的交易日与交易时间、响应元数据中的生成/更新时间、明确的缓存或陈旧标识。
2. 行业双榜、个股、指数或其它累计指标与上一成功档数值完全相同，只能认定为“本次返回值相同”，不能据此推断接口未更新、数据陈旧或第三方异常。
3. 行业接口没有返回可核验时间时，只要本次调用成功、交易日上下文为当天且没有明确陈旧标识，就保留真实返回并继续计算和交付；可在审计数据中记录“行业时间戳未提供”，但不得停止飞书发送。
4. 只有明确旧交易日、旧时间戳落在不应接受的历史时段，或Wind明确返回缓存/陈旧标识时，才终止该档交付；终止时保存实际证据和原始时间字段，不能只写“与上一档一致”。

### 盘中比较

- 最近一周期变化额 = 当前累计主力净流入额 − 上一次成功采样累计值。
- 较基准变化额 = 当前累计值 − 当天首个成功采样值。
- 变化率 = 变化额 ÷ `|比较基准值|` × 100%。基准为0或缺失时显示“不可计算”。
- 若09:30无有效数据，使用当天首个成功采样并注明“首个可用基准”。

### 资金状态

只使用：持续流入、流入转流出、流出收窄、流出扩大、基本持平。

- 当前等于上一值：基本持平。
- 上一值非负且当前非负：持续流入。
- 上一值非负且当前为负：流入转流出。
- 上一值为负且当前不小于上一值：流出收窄。
- 上一值为负且当前更小：流出扩大。

### 收盘趋势

按真实有效固定样本的时间顺序计算相邻增量。零增量既不是正增量也不是负增量。

1. 有效样本少于3：样本不足。
2. 正增量比例不低于80%，且末值高于首值：持续加仓。
3. 负增量比例不低于80%，且末值低于首值：持续减仓。
4. 同时出现正、负增量且末值高于首值：波动加仓。
5. 同时出现正、负增量且末值低于首值：波动减仓。
6. 末值与首值差异绝对值不超过首值绝对值的2%，或两者相等：基本稳定。
7. 其它无法归类情况：基本稳定，并在计算结果中保留各相邻增量供审计。

## 格式与限制

- 所有用户可见金额、涨跌幅、资金占比、变化率、平均收益率和合计值统一保留1位小数。
- 排名、样本数用整数；时间显示到分钟。
- 内部原始值、状态值和中间计算保留Wind原始精度，最后展示时四舍五入。
- 缺失字段写“Wind未返回”，不得补零。
- 首次采样没有上一值时写“基准建立中”。
- 金额统一展示为亿元。
- 飞书精简版使用规定的紧凑表格与字段布局，控制列数和单元格长度；Codex精简版使用等价Markdown表格；完整审计版继续使用规定表格。
- 精简版中的正数显式加 `↑ +`，负数显示 `↓ -`，零值显示 `→ 0.0`；行业个股统一使用 `简称 箭头±资金亿元/箭头±涨跌幅%`。完整审计版可继续使用纯正负号以保持表格紧凑。
- 不给买卖建议。
- 所有用户可见版本均不显示固定的数据来源声明或主力口径免责声明。
- 不把“接口没有提供完整性声明”作为用户提示；仅当实际返回数量不足、字段缺失或时间异常影响结果时，按具体事实提示。
